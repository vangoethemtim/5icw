Les 1

Frontend, backend en data

Een webapp is meer dan een website. De browser toont de interface, maar gegevens en beslissingen kunnen op een andere computer staan.

OnderdeelTaakVoorbeeld
ClientToestel of programma dat iets vraagt.Browser op je laptop.
FrontendWat de gebruiker ziet en bedient.HTML, CSS en JavaScript.
WebserverOntvangt HTTP-verzoeken en stuurt antwoorden.Vite-devserver of PHP-server.
BackendControleert invoer en voert regels uit.PHP-code die een bericht opslaat.
DatabaseBewaart en doorzoekt gegevens.Later: SQLite of MariaDB.
APIDe afgesproken ingang tot de backend.GET /api/berichten.
Statisch tegenover dynamischEen statische pagina stuurt bestaande bestanden terug. Een dynamische app maakt een antwoord op basis van invoer, regels en opgeslagen gegevens.

Wat betekent een URL?

Voorbeeld-URL
https://apps.school.be:443/api/berichten?limit=10
└─┬─┘   └──────┬──────┘└┬┘└──────┬──────┘└───┬───┘
schema         host      poort     pad          query
  • Schema: welk protocol? https is HTTP met versleuteling.
  • Host: welke computer of dienst?
  • Poort: welke ingang? HTTPS gebruikt normaal 443; lokaal zie je vaak 5173 of 8000.
  • Pad: welke bron wil je?
  • Query: extra parameters na ?.
localhost en 127.0.0.1Beide verwijzen naar je eigen computer. http://127.0.0.1:5173 is dus niet automatisch zichtbaar voor de rest van de klas.
1A

Teken de route

Volg de knop “Plaats bericht”.

  1. Teken browser, webserver, backend en opslag.
  2. Zet pijlen voor verzoek en antwoord.
  3. Schrijf bij elke pijl welke gegevens reizen.
  4. Markeer waar invoer gecontroleerd moet worden.
Controle
De browser stuurt tekst; de backend valideert en bewaart; de backend antwoordt met resultaat en statuscode; de browser past de pagina aan.
Les 2

HTTP: verzoek en antwoord

HTTP is de taal waarmee een client en server berichten uitwisselen. Elk verzoek krijgt één antwoord.

Request

Methode + pad + headers + soms een body.

Response

Statuscode + headers + soms een body.

Vereenvoudigd HTTP-verzoek
POST /api/berichten HTTP/1.1
Host: app.school.be
Content-Type: application/json
Accept: application/json

{"tekst":"Hallo klas!"}
Vereenvoudigd HTTP-antwoord
HTTP/1.1 201 Created
Content-Type: application/json; charset=utf-8

{"data":{"id":42,"tekst":"Hallo klas!"}}
HTTP is statelessEen volgend verzoek weet niet vanzelf wat er eerder gebeurde. Inloggen werkt daarom met een cookie of token dat bij volgende verzoeken wordt meegestuurd.

Veelgebruikte methodes

MethodeBedoelingVoorbeeld
GETGegevens lezen.Lijst berichten ophalen.
POSTIets nieuws maken.Nieuw bericht plaatsen.
PUTEen bron volledig vervangen.Volledig profiel overschrijven.
PATCHEen deel wijzigen.Alleen de tekst aanpassen.
DELETEIets verwijderen.Bericht 42 wissen.

Statuscodes zijn het verkeerslicht

CodeBetekenisTypische situatie
200 OKGeluktGET levert gegevens.
201 CreatedAangemaaktPOST maakte een bericht.
204 No ContentGelukt, geen bodyVerwijderen zonder extra antwoord.
400 Bad RequestVerzoek ongeldigJSON is kapot.
401 UnauthorizedNiet aangemeldLogin ontbreekt of is verlopen.
403 ForbiddenGeen toestemmingAangemeld, maar geen beheerder.
404 Not FoundNiet gevondenEndpoint of id bestaat niet.
409 ConflictConflictGebruikersnaam bestaat al.
422 Unprocessable ContentInhoud faalt validatieTekst is leeg of te lang.
500 Internal Server ErrorFout in serverBackend kan bestand niet lezen.
Een fout is ook een correct antwoordEen nette API gebruikt bijvoorbeeld 422 met een duidelijke JSON-fout. Altijd 200 sturen en alleen “error” in de body zetten maakt debuggen moeilijker.
2A

Kies methode en status

Vul eerst zelf in en open daarna de oplossing.

  1. De lijst met berichten opvragen.
  2. Een geldig nieuw bericht bewaren.
  3. Een leeg bericht weigeren.
  4. Bericht 999 verwijderen, maar het bestaat niet.
Oplossing
1: GET + 200. 2: POST + 201. 3: POST + 422. 4: DELETE + 404.
Les 3

JSON en een API-contract

JSON is tekst met een vaste structuur. Frontend en backend spreken vooraf af welke velden ze verzenden.

Geldige JSON
{
  "data": [
    { "id": 1, "tekst": "Welkom!", "auteur": "Ada" },
    { "id": 2, "tekst": "Tot morgen", "auteur": "Linus" }
  ]
}
  • Sleutels en tekst staan tussen dubbele aanhalingstekens.
  • Een object gebruikt accolades; een lijst gebruikt vierkante haken.
  • Booleans zijn true of false; lege waarde is null.
  • JSON heeft geen commentaar en geen komma na het laatste item.
JSON is geen JavaScript-objectZe lijken op elkaar, maar JSON is tekst. JSON.stringify(object) maakt JSON-tekst; JSON.parse(tekst) maakt er in JavaScript weer gegevens van.

Endpoint = methode + pad

MethodePadActieSucces
GET/api/berichtenAlle berichten200
GET/api/berichten/42Eén bericht200 of 404
POST/api/berichtenNieuw bericht201
PATCH/api/berichten/42Bericht aanpassen200 of 404
DELETE/api/berichten/42Bericht verwijderen204 of 404

Die volledige afspraak noemen we een API-contract: endpoints, invoervelden, antwoordvelden, validatie en statuscodes.

3A

Test JSON met opzettelijke fouten

Gebruik de Console in DevTools.

  1. Open DevTools met F12 en kies Console.
  2. Probeer JSON.parse('{"naam":"Ada"}').
  3. Verwijder één dubbel aanhalingsteken en probeer opnieuw.
  4. Lees het regelnummer in de foutmelding.
  5. Zet een JavaScript-object om met JSON.stringify({naam: 'Ada'}).
3B

Ontwerp vóór je codeert

Maak op papier het endpoint “taak voltooid”.

Noteer methode, pad, JSON-input, JSON-output, twee validatieregels en minstens drie mogelijke statuscodes.

Fetch en Network: bewijs het zelf

We bouwen een kleine frontend met mockdata. De vorm van het antwoord is al die van onze latere PHP-API.

Project maken

Opdrachtprompt

npm create vite@latest webapp-werking -- --template vanilla
cd webapp-werking
npm install
mkdir public\api
code .

1. Mock-API maken

Maak public/api/berichten.json:

public/api/berichten.json
{
  "data": [
    { "id": 1, "tekst": "Welkom bij het prikbord", "auteur": "Ada" },
    { "id": 2, "tekst": "De echte backend volgt hierna", "auteur": "Linus" }
  ]
}

2. JavaScript schrijven

Vervang src/main.js door:

src/main.js
import './style.css';

document.querySelector('#app').innerHTML = `
  <main class="container">
    <h1>Klasprikbord</h1>
    <p id="status">Berichten laden…</p>
    <ul id="berichten"></ul>
    <button id="herlaad" type="button">Opnieuw laden</button>
  </main>
`;

const status = document.querySelector('#status');
const lijst = document.querySelector('#berichten');

async function laadBerichten() {
  status.textContent = 'Berichten laden…';
  lijst.replaceChildren();

  try {
    const response = await fetch('/api/berichten.json');

    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }

    const resultaat = await response.json();

    for (const bericht of resultaat.data) {
      const item = document.createElement('li');
      item.textContent = `${bericht.auteur}: ${bericht.tekst}`;
      lijst.append(item);
    }

    status.textContent = `${resultaat.data.length} berichten gevonden.`;
  } catch (error) {
    status.textContent = `Laden mislukt: ${error.message}`;
  }
}

document.querySelector('#herlaad').addEventListener('click', laadBerichten);
laadBerichten();
Waarom async en await?Een netwerkantwoord komt later. await pauzeert alleen deze async-functie tot de Promise klaar is; de browser zelf blijft reageren.
Belangrijk bij fetchEen antwoord met 404 of 500 bereikt normaal nog steeds je code. Daarom test je zelf response.ok. Een echte netwerkfout belandt rechtstreeks in catch.
Veilig tonenDe berichten worden met textContent toegevoegd. Gebruik voor gegevens van gebruikers niet zomaar innerHTML, want de browser kan ingevoerde HTML dan als code uitvoeren.

4A

Onderzoek het verzoek

Niet gokken: kijk in Network.

  1. Open de Vite-URL en daarna DevTools → Network.
  2. Herlaad de pagina.
  3. Klik op berichten.json.
  4. Noteer Request URL, Request Method, Status Code en Content-Type.
  5. Bekijk Preview of Response en zoek de twee berichten.
4B

Maak gecontroleerd een 404

Een fout is een meetbaar onderdeel van de app.

  1. Verander tijdelijk de fetch-URL in /api/bestaat-niet.json.
  2. Voorspel wat status en pagina zullen tonen.
  3. Controleer in Network dat de status 404 is.
  4. Herstel de juiste URL.
4C

Breid het antwoord uit

Verander data en interface.

  1. Voeg aan elk bericht "gemaakt_op": "2026-09-11T10:00:00Z" toe.
  2. Toon de datum in de lijst.
  3. Voeg een derde bericht toe.
  4. Controleer dat de teller automatisch 3 wordt.
