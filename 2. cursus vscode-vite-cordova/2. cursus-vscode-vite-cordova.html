Terminal instellen op CMD

  1. Open de terminal met Ctrl + `.

2A

Praktijk: maak een workspace

Gebruik de Explorer van VS Code, niet Verkenner.

  1. Maak onder Dev de map simpele-website.
  2. Open die map via File → Open Folder.
  3. Bevestig Workspace Trust alleen voor je eigen map.
  4. Maak index.html, style.css en script.js.
  5. Open een terminal en controleer het pad met cd en de bestanden met dir.
Waarom niet zomaar elke map vertrouwen?
Een vertrouwde workspace mag taken, debugconfiguraties en extensiecode activeren. Vertrouw daarom alleen mappen waarvan je de bron kent. Een gedownloade onbekende projectmap moet je eerst bekijken.

script.js

script.js
const actieKnop = document.querySelector('#actie');
const resetKnop = document.querySelector('#reset');
const statusTekst = document.querySelector('#status');

let aantal = Number(localStorage.getItem('aantalKlikken') ?? 0);

function toonAantal() {
  statusTekst.textContent = `Aantal klikken: ${aantal}`;
}

actieKnop.addEventListener('click', function () {
  aantal = aantal + 1;
  localStorage.setItem('aantalKlikken', aantal);
  toonAantal();
});

resetKnop.addEventListener('click', function () {
  aantal = 0;
  localStorage.removeItem('aantalKlikken');
  toonAantal();
});

toonAantal();

Les 4

Node.js, npm en Vite

Vite is geen programmeertaal. Het is ontwikkelgereedschap dat tijdens het werken een snelle lokale server aanbiedt en voor publicatie geoptimaliseerde bestanden bouwt.

BegripBetekenis
Node.jsJavaScript-runtime buiten de browser. Hiermee draaien de Vite- en Cordova-tools.
npmPakketbeheerder en script runner die met Node.js wordt geïnstalleerd.
package.jsonProjectmanifest met naam, scripts en afhankelijkheden.
package-lock.jsonLegt exacte pakketversies vast zodat installaties reproduceerbaar blijven.
node_modulesLokale kopieën van geïnstalleerde pakketten. Groot en opnieuw opbouwbaar met npm install.
dev serverLokale server die wijzigingen snel in de browser toont, inclusief Hot Module Replacement.
buildZet bronbestanden om naar compacte productie-uitvoer in dist.

Een vanilla Vite-project maken

Opdrachtprompt
cd /d "%USERPROFILE%\Dev"
npm create vite@latest mijn-vite-app -- --template vanilla
cd mijn-vite-app
npm install
npm run dev

Open het lokale adres dat Vite toont, normaal http://localhost:5173. Laat de terminal draaien. Stop de server pas op het einde met Ctrl + C.

Waarom tweemaal --? Het eerste -- vertelt npm dat de volgende opties voor create-vite bedoeld zijn. --template vanilla kiest gewone JavaScript zonder framework.

├───public             ← bestanden die ongewijzigd meekomen

  3. Wijzig een kleur in src\style.css en sla op.
  4. Controleer dat de browser automatisch bijwerkt.
  5. Bekijk package.json en zoek de scripts dev, build en preview.

Cordova plaatst HTML, CSS en JavaScript in een native appcontainer met een WebView. Via plugins kan JavaScript later functies van het toestel gebruiken, zoals camera, bestanden of trillen.

Cordova CLI installeren

Opdrachtprompt
npm install -g cordova
cordova --version
where cordova

De optie -g installeert de CLI globaal, zodat het commando cordova in elke projectmap beschikbaar is.

Een Cordova-project maken

Opdrachtprompt
cd /d "%USERPROFILE%\Dev"
cordova create mijn-cordova-app be.sfevergem.jouwvoornaam.mijnapp MijnApp
cd mijn-cordova-app
cordova platform add browser
cordova platform ls
cordova run browser

Vervang jouwvoornaam door je eigen voornaam, zonder spaties of accenten. Zo krijgt elke leerling een eigen app-ID.

OnderdeelFunctieHandmatig bewerken?
wwwWebbestanden die in de app terechtkomenJa, of laten vullen door Vite
config.xmlApp-ID, naam, voorkeuren en platformconfiguratieJa
package.jsonnpm-pakketten, Cordova-platforms en pluginsVoorzichtig
platformsGegenereerde native platformprojectenNee
pluginsGeïnstalleerde Cordova-pluginsNee
Bewerk nooit rechtstreeks platforms Cordova kan die map bij prepare, een update of het opnieuw toevoegen van een platform overschrijven. De bron hoort in www, config.xml en je pakketconfiguratie.
5A

Praktijk: Cordova in de browser

De browserplatform-route vereist geen Android SDK.

  1. Open mijn-cordova-app in VS Code.
  2. Zoek in www\index.html de zichtbare titel en wijzig die.
  3. Voer cordova run browser opnieuw uit.
  4. Open config.xml en zoek je widget-ID be.sfevergem.jouwvoornaam.mijnapp en naam MijnApp.
  5. Voer cordova platform ls uit en controleer dat browser geïnstalleerd is.
Wat betekenen de drie argumenten van cordova create?
mijn-cordova-app is de mapnaam, be.sfevergem.jouwvoornaam.mijnapp is de unieke reverse-domain app-ID en MijnApp is de zichtbare appnaam.
Les 6

Vite koppelen aan Cordova

Vite beheert de broncode en maakt de productiebuild. Cordova neemt die gebouwde bestanden uit www en verpakt ze voor een doelplatform.

Dev \ mijn-vite-app broncode + mijn-cordova-app appcontainer

Maak vite.config.js

Maak dit bestand in de hoofdmap van mijn-vite-app, naast package.json.

vite.config.js
import { defineConfig } from 'vite';

export default defineConfig({
  base: './',
  build: {
    outDir: '../mijn-cordova-app/www',
    emptyOutDir: true
  }
});
InstellingWaarom?
base: './'Laat Vite relatieve assetpaden genereren. Dat werkt ook wanneer Cordova bestanden niet vanaf de root van een gewone website laadt.
outDirStuurt de productiebuild rechtstreeks naar Cordova’s webmap.
emptyOutDir: trueMaakt de doelmap voor elke build leeg, zodat oude gegenereerde bestanden niet blijven staan.
Controleer outDir vóór je bouwt Vite maakt deze doelmap bewust leeg. Ze moet exact naar mijn-cordova-app\www wijzen, nooit naar Dev, je profielmap of een map met eigen bronbestanden.

Bouwen en uitvoeren

Opdrachtprompt
cd /d "%USERPROFILE%\Dev\mijn-vite-app"
npm run build
cd ..\mijn-cordova-app
cordova run browser

Praktijk: bewijs de koppeling

Een wijziging mag pas in Cordova verschijnen na een nieuwe build.

  2. Wijzig daarna een duidelijke titel in de Vite-broncode.

  4. Voer npm run build uit en start Cordova opnieuw.

Les 7

Een Android-app bouwen

Voor de browserplatform-test volstaat Node.js. Een echte Android-build heeft daarnaast JDK 17, Android Studio, de passende Android SDK-onderdelen en een werkende Gradle-installatie nodig.

Actuele combinatie voor deze cursus Cordova-Android 15.0.x gebruikt JDK 17, Node.js vanaf 20.17 of 22.9, Android API 24–36 en Build Tools 36.0.0. Dit blok hoort bij een vooraf voorbereide lescomputer.

JDK en Android Studio installeren

Opdrachtprompt
winget install --id Microsoft.OpenJDK.17 -e --source winget
winget install --id Google.AndroidStudio -e --source winget

Android Studio eenmaal voorbereiden

  1. Start Android Studio en voltooi de eerste configuratie.
  2. Open Tools → SDK Manager → SDK Platforms en installeer Android API 36.
  3. Installeer onder SDK Tools: Android SDK Build-Tools 36.0.0, Command-line Tools (latest) en Platform-Tools.
  4. Installeer Android Emulator alleen als je een virtueel toestel gebruikt.
  5. Sluit daarna VS Code en alle terminals en open ze opnieuw.

Omgevingsvariabelen controleren

Nieuwe opdrachtprompt
java -version
echo %JAVA_HOME%
echo %ANDROID_HOME%
where adb

JAVA_HOME moet naar de hoofdmap van JDK 17 wijzen en ANDROID_HOME normaal naar %LOCALAPPDATA%\Android\Sdk. Voeg in de Windows-omgeving onder PATH minstens de concrete mappen %ANDROID_HOME%\platform-tools en %ANDROID_HOME%\cmdline-tools\latest\bin toe. Open daarna opnieuw een terminal.

Gradle-versie Installeer de door de gebruikte Cordova-Android-versie ondersteunde Gradle-versie en voeg de map bin toe aan PATH. Kies niet blind de nieuwste versie; controleer daarna altijd met cordova requirements android.

Platform toevoegen en APK bouwen

Opdrachtprompt — mijn-cordova-app
cd /d "%USERPROFILE%\Dev\mijn-cordova-app"
cordova platform add android@15
cordova platform ls
cordova requirements android
cordova build android

Na een geslaagde debugbuild staat de APK normaal in:

Uitvoerpad
platforms\android\app\build\outputs\apk\debug\app-debug.apk

Uitvoeren op emulator of toestel

Opdrachtprompt
adb devices
cordova emulate android
cordova run android --device

Gebruik óf een draaiende emulator, óf een Android-toestel met ontwikkelaarsopties en USB-debugging. adb devices moet precies één bruikbaar doel tonen.

7A

Praktijk: requirements lezen

Een foutmelding is hier een diagnose, geen mislukking.

  1. Voer cordova requirements android uit.
  2. Noteer per onderdeel: gevonden versie, vereist of ontbrekend.
  3. Controleer dat Node.js en Java de juiste hoofdversie hebben.
  4. Bouw pas als alle vereisten groen zijn.
  5. Zoek na een geslaagde build de debug-APK via VS Code Explorer.
Eindproef

Van idee tot Cordova-build

Maak een kleine “klasreactie”-app waarin een leerling één van drie reacties kiest. De gekozen reactie, kleur en tijd moeten zichtbaar blijven na herladen.

★

Functionele eisen

Werk in de Vite-broncode; Cordova www blijft gegenereerde uitvoer.

  1. Toon een titel, korte uitleg en drie knoppen: Begrijp ik, Twijfel en Hulp nodig.
  2. Elke keuze geeft een eigen achtergrondkleur.
  3. Toon de laatste keuze en het tijdstip in de pagina.
  4. Bewaar de laatste keuze in localStorage.
  5. Voeg een resetknop toe die de opgeslagen keuze verwijdert.
  6. De interface werkt op een scherm van 360 px breed zonder horizontaal scrollen.

Technische oplevering

  • npm run dev start zonder fout.
  • npm run build vult Cordova www.
  • cordova run browser toont de juiste app.
  • In DevTools Console staan geen rode fouten.
  • De leerling kan package.json, node_modules, dist/www en platforms mondeling verklaren.

Bewijs

Lever de Vite-bronmap in zonder node_modules, plus één schermafbeelding van Cordova Browser. Op een voorbereide Android-pc hoort ook app-debug.apk bij de demonstratie, niet bij de broncode.

Je beheerst nu de keten Broncode schrijven → lokaal ontwikkelen → dependencies installeren → productiebuild maken → webbestanden in een appcontainer verpakken → op een doelplatform testen.
